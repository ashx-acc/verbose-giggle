# Chicago Crime Analytics — Capstone

End-to-end Python data pipeline, SQLite warehouse, FastAPI CRUD API, and a
styled HTML/CSS dashboard for the Accenture × Chicago Police Department crime
analytics case study.

> **Database choice:** Python's built-in `sqlite3` only. No SQLAlchemy, no ORM.
> The app reads and writes the existing `chicago_crime.db` file.

### Why FastAPI + HTML/CSS instead of Streamlit?

FastAPI was chosen because the brief asks for **both** a CRUD API and a
dashboard. One FastAPI app gives you:

1. A real REST API with **POST / PUT / PATCH / DELETE**.
2. Automatic Swagger documentation at `/docs` — excellent for screenshots.
3. Pydantic validation and clean 4xx error responses.
4. A normal HTML/CSS dashboard that can be printed or exported as a PNG.
5. No second server or extra runtime, unlike a separate Streamlit app.

Streamlit is great for quick notebooks, but it is not a natural fit for a
CRUD REST API. The HTML/CSS route keeps the whole submission in one process.

## 3. Database design

### Fact table: `crime`

24 columns from the cleaned notebook output:

```text
id, case_number, date, block, iucr_code, primary_type, description,
location_desc, arrest, domestic, beat_num, district_code, ward_no,
community_code, fbi_code, x_coordinate, y_coordinate, Year, Month,
DayOfWeek, date_of_update, latitude, longitude, location
```

### Dimension table used for CRUD: `community`

```text
community_code (PK), community_name, population, area_sqmile,
area_sqkm, density_per_sqmi, density_per_sqkm
```

This is the City/community dimension referenced by `crime.community_code`.
It is the table used by the browser CRUD screen and the `/api/community` API.

### Reporting views

- `vw_crime_yearly` — year, crime count, arrest count, arrest rate.
- `vw_crime_by_category` — primary type, count, percentage.

## 4. CRUD API

Base URL: `http://127.0.0.1:8000`

| Method | Endpoint | Purpose | Success |
|---|---|---|---|
| GET | `/api/community` | List rows. Optional `?search=Austin` | 200 |
| GET | `/api/community/{code}` | Read one row | 200 / 404 |
| POST | `/api/community` | Create a row | 201 / 409 / 422 |
| PUT | `/api/community/{code}` | Full replace | 200 / 404 / 409 |
| PATCH | `/api/community/{code}` | Partial update | 200 / 400 / 404 / 409 |
| DELETE | `/api/community/{code}` | Delete a row | 204 / 404 |
| GET | `/api/community/{code}/crime-summary` | Crime + arrest counts | 200 / 404 |
| GET | `/api/dashboard/insights` | KPIs and insights JSON | 200 |
| GET | `/dashboard/export` | Download PNG report | 200 |

## 9. Data notes and caveats

- The raw CSV has one malformed line (line 498: 21 fields instead of 20).
  pandas skips it with `on_bad_lines="warn"`, leaving **496 usable rows**.
- **488 of 496 rows are from 2016.** Year-over-year comparisons are directional,
  not a true five-year crime rate.
- 2012–2015 contain only 1–4 records each, so their arrest rates (100%, 100%,
  0%, 50%) are unstable.
- The source CSV has no time-of-day field. `synthetic_hour` is generated with
  `numpy.random.default_rng(seed=42)` and is clearly labelled as synthetic in
  the dashboard and report.
- The dashboard is for prioritisation and storytelling, not causal inference.

## 12. Troubleshooting

| Problem | Fix |
|---|---|
| `ModuleNotFoundError: fastapi` | `pip install -r requirements.txt` |
| Port 8000 already in use | `python run.py` uses 8000; change the port in `run.py` |
| Dashboard is empty | `python -m app.seed` to rebuild from `data/processed` |
| Database locked | Close other SQLite/Jupyter connections, then retry |
| Charts look stale | Refresh the page; chart URLs include a cache-busting version |
| Want a different CRUD table | Copy the `community` pattern in `crud.py` and `main.py`; the same SQL approach works for `district`, `iucr`, `ward_office`, or `police_beat` |
